# Amazon-Abrechnung zu DATEV: Settlement-Bericht im Browser in einen DATEV-Buchungsstapel umwandeln

Built by an automated studio. Read `SPEC.md` (what and why), `PLAN.md` (the task list) and this file (how) before changing anything.

## Rules for every contributor, human or agent

- Never commit secrets. Environment variable names go in `.env.example`, values never do.
- Payments stay in test mode until the owner goes live.
- Do not run `git commit` or `git push`. The studio orchestrator commits.
- `npm test` and `npm run build` must pass before work counts as done.
- Pages that answer a search query must be real tools or substantive answers, never thin filler.

## Stack, layout and commands

**Stack:** Astro 7 (static output, TypeScript strict) + Preact island for the converter (`@astrojs/preact`), `@astrojs/sitemap`, Vitest 5. No Tailwind and no UI kit: the design is one token stylesheet plus scoped component styles (see DESIGN.md). Fonts are self-hosted via `@fontsource-variable/archivo` and `@fontsource/ibm-plex-mono` (imported in `src/layouts/Base.astro`). ZIP via `fflate`. Server side = Cloudflare Pages Functions (`functions/`) with a KV binding `LICENCES`; logic lives in `server/` so it can be unit-tested without Cloudflare. No Stripe SDK: Stripe is called with `fetch` and form-encoded bodies, signatures are checked with Web Crypto.

**Commands** (all exit on their own; never run `astro dev`/`astro preview`):

| Command | What |
|---|---|
| `npm test` | `vitest run` over `src/**/*.test.ts`, `server/**/*.test.ts`, `functions/**/*.test.ts`, `tests/**/*.test.ts` |
| `npm run build` | `astro check` (types) + `astro build` into `dist/` |
| `npm run build:preview` | build with `SITE_URL=https://example.github.io SITE_BASE=/preview` to prove sub-path handling |
| `npm run lint` | `astro check` |
| `npm run design-check` | studio design check (`scripts/design-check.mjs`, maintained by the studio, do not edit) |
| `npm run size` | gzip sizes of JS/CSS in `dist/`, fails above 90 KB JS (run after a build) |

**Conventions**

- Base path: `astro.config.mjs` reads `SITE_URL` and `SITE_BASE`. Never hard-code `/something` in an href or src; use `withBase('/something/')`. In the island, use `import.meta.env.BASE_URL` through `withBase` too, including the licence API URL.
- Money is integer **cents** everywhere in `src/lib`; format to `1.234,56` only at the edge (UI) and `1234,56` in the EXTF writer.
- Core logic in `src/lib` is pure TypeScript with no DOM access, so it is tested in Node. The island only wires UI to it.
- Client code makes exactly one kind of network call: `POST /api/licence/check` with `{licenceKey, hash}`. Never send file content, amounts, order IDs or plain Berater-/Mandantennummer anywhere. Checkout is a plain HTML form POST to `/api/checkout`, not a fetch.
- On the GitHub Pages preview there are no Functions: the tool must still work fully up to the paywall, and the plans dialog says purchase is not available there.
- UI text is German, formal "Sie", voice as in DESIGN.md. Errors name the row and the value.
- Look: follow DESIGN.md (brand "Grünband"); tokens and base styles live in `src/styles/brand.css`. No gradients anywhere, no coloured side borders, no rounded cards, no shadows except the flat zero-blur "Durchschlag" offset from brand.css, no icon packs, no emoji. Illustrations are in `public/art/`, the mark in `public/brand/logo.svg`. Numbers in IBM Plex Mono with tabular numerals. Run `npm run design-check` after any style change.
- Analytics: Cloudflare Web Analytics only, cookie-free, loaded when `PUBLIC_CF_BEACON_TOKEN` is set. Events carry names only, never data.
- DATEV format: EXTF header version 700, category 21, "Buchungsstapel", format version 13; all column names live in `src/lib/datev/columns.ts` with the source URL in a comment. Windows-1252, CRLF, `;`, decimal comma.
- Fixtures are synthetic and say so; never present them as real Amazon data.
- Environment variable names are in `.env.example`.
